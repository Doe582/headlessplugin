3. PRODUCTS & STORE DATA
--------------------------------------------------------------------------------
Base URL: http://localhost/styluzawebtx/wp-json/wc/store/v1

GET    /products
       Query params:
       - page, per_page (default 1 / 10)
       - search (matches product title/description)
       - category, tag, attribute filters (see section 4)
       - on_sale, featured, stock_status
       - orderby=price|price-desc|rating|newest etc.
       Sample curl:
       curl -X GET "http://localhost/styluzawebtx/wp-json/wc/store/v1/products?per_page=12&page=1"

GET    /products/{id}
       Returns the complete Store API product payload including prices, images,
       variations, stock, add-to-cart data, links, etc.
       curl -X GET http://localhost/styluzawebtx/wp-json/wc/store/v1/products/210

GET    /products/{id}/variations
       Available for variable products; supports page/per_page.

GET    /collections
       Returns all Store API collections (featured, top-rated, new arrivals, etc.).
       Each collection describes slug, label, description, default ordering.

GET    /collections/{slug}
       Query parameters: page, per_page, orderby (same as /products).
       Returns products scoped to the collection logic (e.g., featured products).
       Sample curl:
       curl -X GET "http://localhost/styluzawebtx/wp-json/wc/store/v1/collections/featured?per_page=8"

HEADERS:
- X-WC-Store-API-Nonce: required when calling from same origin with cookies.
- Authorization: Bearer <token> (optional, maps to logged-in user).

NOTES:
- All responses include pagination headers (`X-WP-Total`, `X-WP-TotalPages`).
- Use `?_fields[]=id&_fields[]=name` to limit payload size if needed.
- Combine with section 4 filters for taxonomy/price filtering.

--------------------------------------------------------------------------------
4. PRODUCT FILTERS (Store API)
--------------------------------------------------------------------------------

The Store API products endpoint supports dynamic filtering via query parameters.

Taxonomy Filters:
All taxonomy filters accept comma-separated term IDs, slugs, or names (case-insensitive).
The filter will try to match in this order: term ID → slug → name.

Color Filter:
GET    /products?color=Red,Blue
GET    /products?color=red,blue
GET    /products?color=1,2,3

Size Filter:
GET    /products?size=Small,Medium,Large
GET    /products?size=small,medium,large
GET    /products?size=5,6,7

Region Filter:
GET    /products?region=Rajasthan,Gujarat
GET    /products?region=rajasthan,gujarat
GET    /products?region=10,11

Fabric Filter:
GET    /products?fabric=Silk,Cotton
GET    /products?fabric=silk,cotton
GET    /products?fabric=20,21

Stock Status Filter:
GET    /products?stock_status=instock
Values: instock, outofstock, onbackorder

On Sale Filter:
GET    /products?on_sale=true
Values: true, 1, false, 0

Price Range Filters:
GET    /products?min_price=1000&max_price=50000
GET    /products?min_price=0
GET    /products?max_price=10000

Category Filter:
GET    /products?category=sarees,lehengas
GET    /products?category=1,2,3

Combining Multiple Filters:
GET    /products?color=red&size=M&fabric=silk&min_price=1000&max_price=50000&stock_status=instock&on_sale=true

Taxonomy Naming:
The plugin automatically detects taxonomy names using:
1. pa_{name} - WooCommerce product attribute format (e.g., pa_color, pa_size)
2. product_{name} - Custom taxonomy format (e.g., product_color, product_size)
3. {name} - Direct name (e.g., color, size)

Sort Options:
The API response includes sort_options field with available sorting:
- menu_order - Default sorting (as set in admin)
- popularity - Sort by popularity
- rating - Sort by average rating
- date - Sort by latest (newest first)
- price - Sort by price: low to high
- price-desc - Sort by price: high to low
- featured - Sort by Featured (custom option)

Example Response:
{
  "products": [...],
  "sort_options": [
    {"value": "menu_order", "label": "Default sorting"},
    {"value": "popularity", "label": "Sort by popularity"},
    ...
  ]
}

Complete Example:
GET    /products?color=red,blue&size=M,L&region=rajasthan&fabric=silk,cotton&min_price=1000&max_price=50000&stock_status=instock&on_sale=true&per_page=12&page=1

Notes:
- All taxonomy filters support both term IDs (numeric) and slugs (text)
- Multiple values in taxonomy filters are comma-separated
- Price filters use the product's _price meta field
- Stock status filter checks the _stock_status meta field
- On sale filter uses WooCommerce's built-in sale detection
- All filters are optional and can be used independently or in combination
- Sort options are automatically included in all product listing responses
- The featured sort option is a custom addition that filters and sorts featured products

--------------------------------------------------------------------------------
5. SESSION NOTES
--------------------------------------------------------------------------------
- To create logged-in orders via Store API, include WordPress auth cookies or send
  Authorization: Bearer <token> header (token stored in user meta _api_token).
- For headless clients without browser cookies, capture the set-cookie header from
  GET /cart and reuse it for subsequent requests so cart/session persists.

6. MY ACCOUNT DATA (DEFAULT WORDPRESS + WOO REST)
--------------------------------------------------------------------------------
Base URL: http://localhost/styluzawebtx/wp-json

Authentication:
- Send logged-in WP cookies or Authorization: Bearer <token> (token created via /restbridge/v1/users/token).
- WooCommerce v3 endpoints also accept application passwords or consumer key/secret if preferred.

Dashboard / Profile Card:
GET    /wp/v2/users/me?context=edit
Headers: X-WP-Nonce (or Authorization header)
Returns: name, username, email, avatar_urls, meta (first_name, last_name, billing/shipping IDs).
Sample curl:
curl -X GET \
  -H "Authorization: Bearer <TOKEN>" \
  -H "Content-Type: application/json" \
  https://<SITE>/wp-json/wp/v2/users/me?context=edit

Customer Profile + Addresses:
GET    /wc/v3/customers/{user_id}
PUT    /wc/v3/customers/{user_id}
Payload fields:
{
  "first_name": "Sophia",
  "last_name": "Water",
  "billing": {...},
  "shipping": {...}
}
Use GET result for the left sidebar (avatar/email) and Address tab.
Sample curl (GET):
curl -X GET \
  -H "Authorization: Bearer <TOKEN>" \
  https://<SITE>/wp-json/wc/v3/customers/<USER_ID>

Sample curl (PUT):
curl -X PUT \
  -H "Authorization: Bearer <TOKEN>" \
  -H "Content-Type: application/json" \
  -d '{...payload...}' \
  https://<SITE>/wp-json/wc/v3/customers/<USER_ID>

Orders List:
GET    /wc/v3/orders?customer={user_id}&per_page=20&status=any
Optional params: status=completed,pending | page=2 | orderby=date
Response includes total/count for Dashboard cards.
Sample curl:
curl -X GET \
  -H "Authorization: Bearer <TOKEN>" \
  "https://<SITE>/wp-json/wc/v3/orders?customer=<USER_ID>&per_page=20&status=any"

Single Order Detail:
GET    /wc/v3/orders/{order_id}
Use for Order detail view, includes billing/shipping, line_items, totals, downloadable items.
Sample curl:
curl -X GET \
  -H "Authorization: Bearer <TOKEN>" \
  https://<SITE>/wp-json/wc/v3/orders/<ORDER_ID>

Customer Downloads:
GET    /wc/v3/customers/{user_id}/downloads
Use for "Download" tab (returns product name, download_url, access_expires).
Sample curl:
curl -X GET \
  -H "Authorization: Bearer <TOKEN>" \
  https://<SITE>/wp-json/wc/v3/customers/<USER_ID>/downloads

Account Details Form:
PUT    /wc/v3/customers/{user_id}
Body can update name, email, password (use "password" field), billing/shipping data.

Logout:
GET    /wp-login.php?action=logout&_wpnonce=<nonce>
Trigger via browser redirect; for headless clients, open this URL in a new tab to clear cookies.

Notes:
- Call /wp/v2/users/me first to get the authenticated user ID, then reuse it for Woo endpoints.
- All Woo v3 endpoints support ?_fields=... to limit payload size.
- Combine responses client-side to build the My Account dashboard (profile card, quick links, stats).
- Store API session check example:
curl -X GET \
  -H "Authorization: Bearer <TOKEN>" \
  https://<SITE>/wp-json/wc/store/v1/cart

           - title (string, optional): Method title
           - tax_status (string, optional): "taxable" or "none"

       Response: Returns success and updated method object

       Response: Returns {"deleted": true, "instance_id": instance_id}

================================================================================
AUTHENTICATION GUIDE
================================================================================

WordPress REST API supports several authentication methods:

1. APPLICATION PASSWORDS (Recommended for API Clients)
   - Built into WordPress 5.6+
   - Enable in wp-config.php: define('WP_APPLICATION_PASSWORDS', true);
   - Create at: WordPress Admin → Users → Your Profile → Application Passwords
   - Usage: Basic Auth with username:application_password
   
   cURL Example:
   curl -X GET "http://localhost/styluzawebtx/wp-json/restbridge/v1/users" \
     -u "your_username:generated_password"
   
   JavaScript Example:
   fetch('/wp-json/restbridge/v1/users', {
     headers: {
       'Authorization': 'Basic ' + btoa('username:application_password')
     }
   })

2. COOKIE AUTHENTICATION (For Logged-In Browser Users)
   - Works automatically if making requests from same browser where logged in
   - Use credentials: 'include' in fetch
   
   JavaScript Example:
   fetch('/wp-json/restbridge/v1/users', {
     credentials: 'include'
   })

3. BEARER TOKEN (Custom Implementation)
   - Get token: POST /wp-json/restbridge/v1/users/token
   - Body: {"username": "...", "password": "..."}
   - Use: Authorization: Bearer <token>
   
   Example:
   curl -X GET "http://localhost/styluzawebtx/wp-json/restbridge/v1/users" \
     -H "Authorization: Bearer your_token_here"

Permission Requirements:
- Posts: edit_posts capability
- Pages: edit_pages capability
- Comments: moderate_comments capability
- Categories/Tags: manage_categories capability
- Users: list_users capability
- Media: upload_files capability
- Products: manage_woocommerce capability

Security Best Practices:
1. Use Application Passwords instead of account passwords
2. Use HTTPS in production to encrypt credentials
3. Rotate Application Passwords regularly
4. Use least privilege - only grant necessary permissions
5. Store credentials securely - never commit to version control
6. Use environment variables for credentials in production

================================================================================
WOOCOMMERCE STORE API - SIMPLE GUIDE
================================================================================

How It Works:

Guest Users (Non-Logged-In):
- No authentication needed
- Cookies handled automatically - WooCommerce creates woocommerce_session_* cookie
- Session stored in database - wp_woocommerce_sessions table
- Just send cookies - Use credentials: 'include' in fetch

Logged-In Users:
- WordPress cookies - Standard WordPress authentication cookies
- Persistent cart - Automatically saved in user meta
- No Bearer token needed - Just use WordPress login cookies

Quick Examples:

Get Cart:
fetch('/wp-json/wc/store/v1/cart', {
  credentials: 'include' // CRITICAL: Must send cookies
})

Add to Cart (Simple Product):
fetch('/wp-json/wc/store/v1/cart/add-item', {
  method: 'POST',
  credentials: 'include',
  headers: {
    'Content-Type': 'application/json',
    'X-WC-Store-API-Nonce': nonce
  },
  body: JSON.stringify({
    id: 123,
    quantity: 1
  })
})

Add to Cart (Variable Product):
fetch('/wp-json/wc/store/v1/cart/add-item', {
  method: 'POST',
  credentials: 'include',
  headers: {
    'Content-Type': 'application/json',
    'X-WC-Store-API-Nonce': nonce
  },
  body: JSON.stringify({
    id: 123,
    quantity: 1,
    variation: [
      { attribute: 'pa_color', value: 'blue' },
      { attribute: 'pa_size', value: 'medium' }
    ]
  })
})

Getting the Nonce:
- From PHP: $nonce = wp_create_nonce('wc_store_api');
- From JavaScript: const nonce = window.wcStoreApiNonce;
- Extract from cart response (if available)

Important Points:
1. Always send cookies - Use credentials: 'include' in fetch
2. Nonce required - Get from WordPress
3. No custom code needed - WooCommerce handles everything automatically
4. Guest users - Just use cookies, no authentication
5. Logged-in users - Use WordPress login cookies, no Bearer token needed

Session Management:

Guest Users:
- Session stored in wp_woocommerce_sessions table
- Cookie: woocommerce_session_<hash>
- Automatically created on first request
- Persists via cookie

Logged-In Users:
- WordPress auth cookie: wordpress_logged_in_<hash>
- WooCommerce session cookie: woocommerce_session_<hash>
- Persistent cart in user meta: _woocommerce_persistent_cart_{blog_id}
- Automatically synced

Testing with cURL:

Guest User:
curl -X GET "http://localhost/styluzawebtx/wp-json/wc/store/v1/cart" \
  -H "X-WC-Store-API-Nonce: <nonce>" \
  -c cookies.txt

curl -X POST "http://localhost/styluzawebtx/wp-json/wc/store/v1/cart/add-item" \
  -H "Content-Type: application/json" \
  -H "X-WC-Store-API-Nonce: <nonce>" \
  -b cookies.txt \
  -c cookies.txt \
  -d '{"id": 123, "quantity": 1}'

Logged-In User:
curl -X GET "http://localhost/styluzawebtx/wp-json/wc/store/v1/cart" \
  -H "X-WC-Store-API-Nonce: <nonce>" \
  -b "wordpress_logged_in_<hash>=<value>; woocommerce_session_<hash>=<value>"

NOTES
================================================================================

1. All endpoints use namespace: restbridge/v1
2. Replace "localhost/wooautopublix" with your actual domain
3. Most POST/PUT/DELETE endpoints require authentication
4. GET endpoints are generally public (except users, orders, reports, settings)
5. Query parameters are passed as URL parameters (e.g., ?per_page=10&page=2)
6. POST/PUT request bodies should be JSON with Content-Type: application/json
7. Cart endpoints use WooCommerce session cookies (no auth required)
8. All dates should be in YYYY-MM-DD format
9. All prices/amounts should be numeric or string format (e.g., "10.00")
10. For file uploads (media), use multipart/form-data
